Self-hosted uptime monitor

Hora keeps the hours, so you can sleep.

One small binary checks your services, keeps their history, and serves a calm status page. It wakes you only when something has really broken: never for a blip.

Get started See a status page
# one container, about 15 MB
docker run -d -p 8787:8787 \
  -v "$PWD/hora-config:/etc/hora" \
  -v hora-data:/data ghcr.io/uplg/hora

Why Hora

Flapping never wakes you up

A failed check is retried, an outage needs several failures in a row and a second place to agree, and ten services down behind one database send one alert: the cause.

One small binary

HTTP, TCP, ping, DNS and push checks, SQLite, the status page and ten alert channels in one static binary. No Node, no Redis, no browser running in the background.

Targets you can keep

Set 99.9 % and Hora shows the downtime you have left, warns when it burns too fast, and writes the monthly report for you.

A page people trust

Plain words on every state, light and dark, readable on a phone, fast with 700 services. Also as an Atom feed, JSON and badges.

From a blip to an alert, or not

  1. A check failsRetried at once. A single blip stops here and leaves no trace.
  2. It fails again3 failures in a row (you choose) before anything is called down.
  3. Others agreePeers in other places check too: a local network hiccup is not an outage.
  4. Find the causeServices that depend on a down one are grouped under it.
  5. One alertThe cause and what it affects. Then quiet until it recovers.
