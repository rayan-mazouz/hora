## Why Hora

<CardGrid>
	<Card title="Flapping never wakes you up" icon="moon">
		A failed check is retried, an outage needs several failures in a row and,
		if you run peers, a second place to agree. Ten services down behind one
		database send one alert: the cause.
	</Card>
	<Card title="One small binary" icon="server">
		HTTP, TCP, ping, DNS, push and exec checks, SQLite, the status page and ten
		alert channels in one static binary. The Docker image is about 15 MB. No
		Node, no Redis, no browser in the background.
	</Card>
	<Card title="Targets you can keep" icon="analytics">
		Set 99.9 % and Hora shows the downtime you have left, warns when it burns
		too fast, and writes the monthly report for you.
	</Card>
	<Card title="A page people trust" icon="laptop">
		Server-rendered, no JavaScript framework, readable on a phone. Also as plain text
		for curl, an Atom feed, JSON and badges.
	</Card>
</CardGrid>

## From a blip to an alert, or not

<ol class="hora-flow">
	<li><strong>A check fails</strong><span>Retried at once. A single blip stops here and leaves no trace.</span></li>
	<li><strong>It fails again</strong><span>3 failures in a row (you choose) before anything is called down.</span></li>
	<li><strong>Others agree</strong><span>Peers in other places check too: a local network hiccup is not an outage.</span></li>
	<li><strong>Find the cause</strong><span>Services that depend on a down one are grouped under it.</span></li>
	<li class="end"><strong>One alert</strong><span>The cause and what it affects. Then quiet until it recovers.</span></li>
</ol>

The whole path, with the settings behind each step, is in [Concepts](./concepts/).

## How it compares

<div class="hora-compare">

| | Hora | Uptime Kuma | Gatus |
| --- | --- | --- | --- |
| Runs as | One static binary, ~15 MB image | Node.js app, ~180 MB slim image | Go binary, ~26 MB image |
| Configured in | A TOML file, reloaded live | The web UI | A YAML file |
| N failures before an alert | Yes | Yes (retries) | Yes (failure threshold) |
| One alert for a cascade | Yes, by dependencies | No | No |
| Confirmed from other places | Yes, by peers | No | No |
| Error budget, burn-rate alerts | Yes | No | No |
| Monthly SLA report | Yes, printable | No | No |

</div>

Checked against each project's documentation in October 2026. The details,
sources and what the others do better are in [Why Hora](./why-hora/).

Named after the **Horai**, the Greek goddesses of the hours. Its owl dozes
while all is well.
